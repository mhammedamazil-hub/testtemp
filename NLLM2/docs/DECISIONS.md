# Decisions — Forge (NLLM2)

Each decision records the constraint that forced it, what was chosen, what was
rejected, and how it can be revisited. Written so a fresh session can continue
without the original conversation.

## D1 — Zero third-party dependencies (std only)

**Constraint.** `crates.io`, `static.crates.io`, `index.crates.io` and `docs.rs`
were all unreachable from this sandbox (HTTP 000). Any design needing `serde`,
`axum`, `tokio`, `sqlx` or `lopdf` cannot be built or even resolved here.

**Chosen.** Hand-written everything on the standard library:

| Concern | Module | Notes |
|---|---|---|
| JSON parse/serialise | `json.rs` | strict parser, `obj!` macro, escapes, numbers |
| HTTP/1.1 server | `http.rs` | header cap 64 KiB, body cap 32 MiB, one thread per connection |
| DEFLATE | `inflate.rs` | RFC 1950/1951: stored, fixed and dynamic Huffman |
| PDF text | `ingest/pdf.rs` | object scan, page tree, `Tj/TJ` operators, `/FlateDecode` |
| ZIP (OOXML) | `ingest/zip.rs` | central directory + stored/deflated entries |
| DOCX/PPTX/XLSX | `ingest/ooxml.rs` | WordprocessingML/DrawingML/SpreadsheetML |
| BM25 | `retrieve.rs` | k1=1.2, b=0.75, shallow suffix normaliser |
| Persistence | `store.rs` | one JSON document, atomic tmp+rename, rotating backups |

**Rejected.** Vendoring crates by hand (unverifiable provenance, huge diffs);
substituting Python/Node for the core (forbidden by the brief).

**Revisit when** network access allows a real dependency set: `serde`, `rustls`,
`pdf-extract` would each delete hundreds of lines — but the module boundaries were
drawn so each can be swapped behind the same function signatures.

## D2 — Persistence: JSON document store, not a database

**Constraint.** No SQLite crate. Data volumes for a personal notebook are small
(hundreds of sources, thousands of chunks).

**Chosen.** `data/db.json` with an in-process `Mutex<Db>`, write-through on every
mutation, `db.json.tmp` + `rename` for atomicity, timestamped copies in
`data/backups/`, and a decoder that falls back to an empty database rather than
crashing on corruption (tested).

**Trade-off.** Whole-file rewrites are O(corpus) per mutation. Acceptable below
~10⁴ chunks; a chunk-log or per-notebook files would be the next step.

## D3 — Modular monolith: `forge-core` + `forge-server`

**Chosen.** All logic in `forge-core` (testable without sockets); `forge-server` is
a thin binary that binds a port and delegates. Static hosting lives in
`forge_core::web` so it is covered by the same test suite.

## D4 — Grounded answers are extractive by default

**Constraint.** No API keys, no network, no model weights, and the mission forbids
faking evidence.

**Chosen.** The engine retrieves passages with BM25, picks the best-matching
sentence from each, and composes an answer that only quotes source text. It
abstains (`abstained: true`, no citations) when every hit falls below
`EVIDENCE_FLOOR = 0.35`. `validate_citations` independently re-checks that each
quote is literally present in its chunk and that source/chunk ids exist, so even a
future model provider cannot emit an unchecked citation.

**Rejected.** Template answers dressed up as model output; describing the product
as "AI answers" when it is quotation.

## D5 — Provider seam is real, and honest about availability

`providers::Answerer` has two implementations: `ExtractiveAnswerer` (always
available) and `RemoteAnswerer` (OpenAI-compatible, `available() == false` in this
build because HTTPS is impossible). `providers::select` never returns "none", and
`chat` returns `engine` plus `engine_note` telling the user which engine answered
and why. Keys are stored in `data/secrets.json` with mode `0600` and are never
echoed by any endpoint (`key_set: true|false` only) — both properties are tested.

## D6 — API-first, static-UI-second

The web app is plain ES modules calling `/api`. No bundler, no npm runtime deps, so
the whole product is one `cargo build`. The UI reads `/api/capabilities` to decide
what to show and what to label unsupported — the capability matrix cannot drift
from the code because it is generated by the code.

## D7 — Locators are structured, not string offsets

`Locator { kind, page, paragraph, row, section, start, end }`. PDFs use pages,
DOCX paragraphs, PPTX slides, spreadsheets rows, Markdown/HTML paragraphs. The
citation carries `locator` plus a human `locator_label`, and the viewer re-fetches
`/sources/{id}/chunks` and highlights the cited chunk — clicking a citation always
lands on real text, never a dead link.

## D8 — Ingestion is fail-loud

Every parse path returns `Result<_, String>`; failures are stored on the source
with `status: "failed"` and the reason, so the UI can show *why* a file did not
import. Unsupported formats return 501/422 with a machine-readable `code`
(`url_ingest_unavailable`, `empty_extraction`, `bad_json`, …). No silent empty
notebooks.

## D9 — Study artifacts are generated, not invented

Flashcards/quiz/report/mindmap/FAQ/summary/narration-script are deterministic
functions of the selected chunks, each item carrying a citation. The quiz's
distractors are drawn from the corpus itself; when a corpus has no numbers it falls
back to key-term cloze rather than emitting nothing. There is no LLM in this path,
and the docs say so.

## D10 — Testing strategy: fixture-driven and end-to-end

Binary fixtures are *generated* (`tests/fixtures/make_pdfs.py`,
`make_ooxml.py`) so they can be rebuilt and audited instead of trusted. The e2e
suite speaks raw HTTP/1.1 to a real socket, and `tests/ui-smoke.js` loads the real
`index.html` + `app.js` in jsdom and clicks through the product. Claims in the docs
point at these tests.

## D11 — URL fetching goes through `curl` as a subprocess, not a Rust HTTP client

**Date.** 2026-10-31. **Constraint.** Documented reference behaviour requires https URL
sources; this build has no TLS crate (D1) and writing a TLS stack is not a responsible
use of the budget.

**Chosen.** `fetch.rs` invokes `curl` with an explicit argv (never `sh -c`), no proxy, no
cookies, no credentials, `--proto`/`--proto-redir` pinned to http/https, and — critically
— `--resolve host:port:ip` with an address that **Forge** resolved and validated as
public. Redirects are not followed by curl (`--max-redirs 0`); Forge reads `Location`,
re-validates and re-pins, capped at 5 hops. Body ≤ 20 MiB, 30 s timeout.

**Rejected.**
* Plain `curl -L`: every redirect hop would escape our policy checks.
* Letting curl do its own DNS: a hostile resolver could answer differently on the second
  lookup (DNS rebinding).
* A hand-written TLS client: enormous attack surface for zero product value.
* A stub that returns "not available": the reference product's URL import is core P0.

**Consequences.** URL ingestion works only where `curl` exists (checked at runtime;
`/api/capabilities` reports the transport and returns `501 fetch_transport_unavailable`
without it). The subprocess is a fork/exec per fetch — acceptable at human scale,
recorded as a scaling limit.

**Revisit when** a TLS-capable HTTP client is available as a dependency: swap the body of
`request_once`, keep the policy layer exactly as it is.

## D12 — Private-network fetching is opt-in and visible, never default

**Date.** 2026-10-31. **Constraint.** The SSRF guard must block loopback/private targets,
but the test suite needs a real HTTP origin to prove the fetch → index → cite path.

**Chosen.** `FORGE_FETCH_ALLOW_PRIVATE=1` is the only way to relax the rule. It is
read at request time, and `/api/capabilities#web_fetch.private_networks` reports
`ALLOWED by FORGE_FETCH_ALLOW_PRIVATE (test mode)` whenever it is set, so an operator
cannot have it silently enabled.

**Rejected.** A `?allow_private=1` query parameter (an attacker-supplied toggle); a
build-time feature flag (would make the tested binary differ from the shipped one).

**Consequences.** Every test that flips the flag holds a process-wide mutex, because the
flag is process-global and tests run concurrently — this bit me once already and is now
explicit in both test suites.

## D13 — A changed source never rewrites existing artifacts; it marks them stale

**Date.** 2026-10-31. **Evidence.** Official help: "When you update or delete a source,
studio outputs generated with that source do not change."

**Chosen.** `POST /api/sources/:id/refresh` re-fetches, compares the SHA-256 of the body,
and re-indexes **only** on change. Artifacts whose notebook is affected get
`stale: true` and the UI says "a source changed after this was generated — regenerate".
Old citations are not silently repointed at new text.

**Rejected.** Auto-regenerating artifacts (destroys evidence provenance); deleting stale
artifacts (destroys user work).
