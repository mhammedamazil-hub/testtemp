# From-zero guide — rebuild Forge without the chat, without a clone

This document assumes:

* you are a different AI (or a person) in a **fresh session**;
* you have **no git clone** and no memory of how Forge was built;
* you may have no network at all;
* you must end up with a working Forge you can open in a browser.

`docs/FROM_ZERO_BUNDLE.md` contains **every source file verbatim**, generated by
`scripts/from_zero_bundle.sh`. If you have the bundle, you have the project.

---

## 0. What you are building

A Rust workspace of three crates plus a static web app:

```
forge/
├── Cargo.toml
├── crates/forge-core/{Cargo.toml, src/*.rs, src/ingest/*.rs, tests/e2e.rs}
├── crates/forge-server/{Cargo.toml, src/main.rs, src/binary.rs}
├── crates/bininspect/{Cargo.toml, src/*.rs}   # APK / PE / ELF analysis
├── apps/web/{index.html, app.js, styles.css, sw.js, manifest.webmanifest, icon.svg}
├── tests/fixtures/{make_pdfs.py, make_ooxml.py, make_apk.py, make_pe.py, *.pdf, *.docx, *.pptx, *.xlsx}
│   └── apk/{AndroidManifest.xml, classes.dex, sample.apk}   # generated, not in the bundle
├── tests/ui-smoke.js
├── scripts/{install-rust.sh, dev.sh, from_zero_bundle.sh}
└── docs/*.md
```

Runtime requirements: a Rust 1.75+ toolchain (1.88.0 used here), a browser. That's
all. No database, no Node for the product, no Python for the product (Python is
only used to *generate* test fixtures).

## 1. Get a Rust toolchain

In a normal environment:

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

**If rustup, static.rust-lang.org and crates.io are blocked** (the case in the
Arena sandbox), use the npm-hosted prebuilt components — this is the route that
actually worked:

```bash
bash scripts/install-rust.sh /tmp/forge-rust     # rustc 1.88.0 + cargo + rust-std
export PATH=/tmp/forge-rust/bin:$PATH
rustc --version && cargo --version
```

The script fetches `@rustbin/rustc-1.88.0-x86_64-unknown-linux-gnu`,
`@rustbin/cargo-…` and `@rustbin/rust-std-…` tarballs from `registry.npmjs.org`
and assembles the prefix layout rustup would produce. It is idempotent.

If nothing works, you cannot build this project: it is Rust, deliberately.

## 2. Recreate the tree

Create the directories, then copy each fenced block from
`docs/FROM_ZERO_BUNDLE.md` into the path given in the `## \`path\`` heading above
it. The map from section to file is exact; nothing is elided and no file is
described instead of shown.

```bash
mkdir -p crates/forge-core/src/ingest crates/forge-server/src crates/bininspect/src \
         apps/web tests/fixtures/apk scripts docs
```

Verify the copy: `wc -l` on each file should match the bundle, and
`cargo metadata --offline` should print three packages without touching the network.

## 3. Regenerate the binary fixtures

PDFs and Office files are generated, not committed as blobs you must trust:

```bash
python3 tests/fixtures/make_pdfs.py     # simple.pdf, flate.pdf
python3 tests/fixtures/make_ooxml.py    # sample.docx, sample.pptx, sample.xlsx
python3 tests/fixtures/make_apk.py      # apk/{AndroidManifest.xml, classes.dex, sample.apk}
python3 tests/fixtures/make_pe.py       # sample.exe
```

The APK and PE fixtures are **not** in the bundle (they are binary). `make_apk.py`
hand-builds a binary `AndroidManifest.xml` (string pool + RES_XML chunks) and a DEX
035 file (string/type/method ids, three `class_def`s); `make_pe.py` writes a PE32+
with a real import directory and a deliberate W+X high-entropy section. Both are
deterministic, so a rebuilt checkout tests identically.

`make_pdfs.py` writes PDF 1.4 by hand (one file uncompressed, one with zlib
`/FlateDecode` streams). `make_ooxml.py` writes ZIP containers with OOXML XML
parts. Both are deterministic.

If Python is unavailable, the two PDF tests will fail with "fixture missing";
every other test still runs.

## 4. Build and test

```bash
export PATH=/tmp/forge-rust/bin:$PATH
cargo build --offline        # must finish with zero deps downloaded
cargo test  --offline        # expect: 20 bininspect + 87 lib + 5 e2e + 5 server = 117 passing
```

Nothing is fetched from crates.io at any point: the crates have no dependencies.

## 5. Run it

```bash
FORGE_ADDR=0.0.0.0:8080 FORGE_DATA_DIR=./data FORGE_WEB_DIR=./apps/web \
  ./target/debug/forge-server
```

Open `http://localhost:8080`. First run creates `./data/db.json`.

Smoke-check without a browser:

```bash
curl -s localhost:8080/api/health
curl -s -X POST localhost:8080/api/notebooks -d '{"title":"Test"}'
```

## 6. Optional: drive the UI headlessly

```bash
npm install jsdom --prefix /tmp/uitest
FORGE_URL=http://127.0.0.1:8080 NODE_PATH=/tmp/uitest/node_modules node tests/ui-smoke.js
```

This loads the real `index.html` + `app.js` in jsdom against a live server on
port 8099 and clicks through library → notebook → source → citation → study tools
→ notes → report → capabilities.

## 7. What to check before trusting a rebuilt copy

| Check | Expected |
|---|---|
| `cargo test --offline` | 117 passing, 0 failing |
| `curl -s localhost:8080/api/capabilities` | `pdf/docx/pptx/xlsx: supported`, `url: blocked`, `audio_overview: unsupported` |
| Upload `tests/fixtures/flate.pdf` | `chunk_count ≥ 2`, `page_count 2`, locators with `page` |
| Ask "what evidence span is retrieved?" | answer quoted from page 2, citation `locator_label: "page 2"` |
| Ask "capital of Mongolia" | `abstained: true`, `citations: []` |
| `POST /api/notebooks/{id}/sources/url` with `http://127.0.0.1` | 422 `url_rejected` |

If any of those differ, read `docs/STATUS.md` (what is real) and
`docs/UNKNOWN_AND_LIMITATIONS.md` (what is not) before changing code.

## 8. Where the design lives

* `docs/DECISIONS.md` — why std-only, why JSON storage, why extractive answers.
* `docs/SECURITY.md` — SSRF/traversal/secret handling and their tests.
* `docs/TEST_MATRIX.md` — every test name and what it proves.
* `docs/FEATURE_PARITY.md` — how Forge compares to NotebookLM, labelled honestly.
* `docs/USER_REQUIREMENTS.md` — the brief's requirements and their status.

## 9. Forbidden shortcuts

* Do not "fix" a failing test by deleting it; the tests are the only proof the
  product works.
* Do not add a network dependency to claim a feature (URL ingestion, LLM calls)
  that the build cannot honour — return the documented 501 instead.
* Do not describe unimplemented features as working. The capability endpoint is
  the single source of truth and the UI mirrors it.
