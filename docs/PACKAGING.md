# Packaging and distribution

| Target | How | Status in this environment |
|---|---|---|
| Web / PWA | `npm run build` → `dist/`; `npm run package:web` → `release/sourceforge-web-*.zip` | built, validated, served |
| Linux `.deb` | `npm run package:linux` → `release/sourceforge_<ver>_all.deb` | built, unpacked, payload served on loopback |
| Windows portable | `npm run package:windows` → `release/sourceforge-<ver>-windows-portable.zip` | built; launcher written but not executed (no Windows) |
| Android APK | `npx cap sync android && cd android && ./gradlew assembleDebug` | project generated; **build blocked** (no JDK/Android SDK, Gradle distribution unreachable) |
| GitHub Pages | `.github/workflows/ci.yml` job `pages` | configured, never executed |

## Web / PWA

```
dist/
  index.html
  assets/index-*.js, *.css, chunk-*.js …
  manifest.webmanifest
  sw.js
  icons/icon.svg, icon-192.png, icon-512.png, maskable-512.png, apple-touch-icon.png
```

`scripts/validate-build.mjs` enforces: shell + manifest + service worker + icons exist,
the manifest is valid and installable (192/512 + maskable), `index.html` links it and
uses relative asset paths (works under a sub-path like GitHub Pages), the service worker
has install/fetch handlers and a versioned cache, and no secret-shaped strings are in the
bundle. Any failure exits non-zero, so CI cannot publish a broken artifact.

The service worker:

* caches the shell (`./`, `index.html`, manifest, icons) at install;
* network-first for navigations with a cached `index.html` fallback;
* stale-while-revalidate for same-origin static assets;
* never caches cross-origin requests (provider APIs, reader endpoints, GitHub);
* deletes caches from older versions on activate; supports `SKIP_WAITING` and
  `CLEAR_CACHES` messages.

## Linux `.deb`

`scripts/package-linux.sh` builds a real Debian package with `dpkg-deb`:

* payload `/usr/share/sourceforge/` (the same static build),
* launcher `/usr/bin/sourceforge` (POSIX shell) that serves the payload on
  `127.0.0.1:8787` with `python3 -m http.server` and opens the browser,
* desktop entry and 512 px icon under `hicolor`,
* `Depends: python3, xdg-utils`, `Architecture: all`.

The script then inspects the package (`dpkg-deb --info/--contents`), extracts it, checks
the launcher's syntax, starts `http.server` on the extracted payload and fetches `/`,
`manifest.webmanifest`, `sw.js` and the hashed entry bundle. That verification passed in
this environment.

Why a loopback server: browsers refuse ES modules and service workers on `file://`. The
package does not add a backend or expose anything beyond 127.0.0.1.

## Windows portable

`scripts/package-windows.sh` zips the build plus `Start-SourceForge.cmd` and
`Start-SourceForge.ps1`. The PowerShell launcher is a self-contained `HttpListener`
static server (no Node/Python needed) with path traversal protection, MIME types and an
SPA fallback. The ZIP's contents are verified; the launcher is **not executed here**.

Deliberately not faked:

* no `.msi`/`.exe` installer (needs WiX/NSIS on Windows),
* no Tauri/Electron shell (needs Rust/Electron for Windows).

## Android

`capacitor.config.ts` + `android/` (generated by `npx cap add android`) wrap the built
assets from `dist/` in a WebView with an `https://localhost` origin so IndexedDB, service
workers and fetch behave like the PWA.

Local attempt: `java` is absent and the Gradle distribution cannot be downloaded, so
`./gradlew assembleDebug` was not run and **no APK exists**. CI job `android-apk`
(`setup-java` + `setup-android` + `gradle/actions/setup-gradle`) builds and uploads
`app-debug.apk`; that job has not been executed.

## GitHub Actions

`.github/workflows/ci.yml`:

1. `test-and-build` — `npm ci`, typecheck, tests, build, validate, package web.
2. `browser-tests` — Chromium install + `npm run test:e2e`, upload report.
3. `rust-core` — fmt, clippy, parity tests, `wasm-pack` build, upload wasm package.
4. `linux-package` — build + verify `.deb`, upload.
5. `windows-portable` — build + verify ZIP, upload.
6. `android-apk` — Capacitor sync + Gradle debug APK, upload.
7. `pages` — on pushes to `main`, downloads the wasm artifact (if present), rebuilds and
   publishes `dist/` to GitHub Pages.

Actions are pinned (checkout v4.2.2, setup-node v4.4.0, upload-artifact v4.6.2,
setup-java v4.7.0, etc.). No secrets are required for any job.

## Reproducing the WASM bundle

```bash
rustup target add wasm32-unknown-unknown
cargo install wasm-pack
npm run wasm       # cargo test → wasm-pack build → copies into public/wasm/
npm run build      # the engine loader then activates Rust at runtime
```

Without that step the app runs the TypeScript implementation and says so in the sidebar.
