6. **Android compatibility:** No official Android application module, manifest, Gradle packaging directory, or Android APK recipe found at the pinned upstream tree. The project advertises native desktop and WebAssembly builds. WebAssembly may be a candidate engine/UI distribution route but does not itself prove Android operation or qualify as a native Android integration. Unofficial Android forks exist as investigation leads, not verified canonical support.
7. **Existing editing functionality:** The web frontend builds the same Rust/egui editor to WebAssembly, but the browser entry point inspected does not expose a JavaScript command/control API. File open/save uses browser pickers and downloads. A tool-calling agent therefore needs a reviewed adapter to the actual editor session; generic click automation is not an acceptable substitute. The README describes a real raster editor with layers/groups, masks, adjustment layers, selections, brushes, vector shapes/paths, editable text, transformations, filters, blend modes, PSD/PSB and multiple raster/project formats, undo/history, and export. Treat feature scope as upstream claims pending per-feature Android tests.
8. **Dependencies:** Independent Rust workspace (`crates/*`, `apps/*`, `xtask`), with app, CLI, web, rendering, image codec and text-related crates. Rust >=1.95 is declared. Exact third-party dependency/license inventory and Android native dependency compatibility have not yet been audited from Cargo.lock/build scripts.
9. **Memory requirements:** No measured Android/Tab A9 memory target or per-editor peak usage was verified. Large raster documents, high bit depths, history and compositing make measurement essential; do not infer RAM from desktop claims.
10. **Integration strategy:** An initial single-APK host and WebAssembly bundle workflow now exist in the root project. The host serves local upstream assets and routes to this editor; the web frontend is the actual PhotoCraft engine/UI. Next prove SAF image open, real layer edit, native project save/reopen and export on Android. Do not claim a verified integration until that round trip passes.
11. **Known blockers:** No official Android app/build recipe; Android WebView GPU/input/lifecycle/SAF and blob-export behavior unverified; web frontend has no command API for the AI; browser autosave/recovery differs from desktop; app bundle and device memory unknown; asset/dependency licenses need inventory.
